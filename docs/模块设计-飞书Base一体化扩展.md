# 个人混合管理系统 2.0 — 完整方案

> 基于飞书Base一体化扩展（方案A），融入"十年之河"系统精华
> 设计原则：消除模糊 · 输入即完成 · <5min日常维护
> 最后更新：2026-06-29

---

## 零、系统哲学

### 核心理念：消除模糊

> 大脑不擅长应对模糊。明确任务和记录能减少焦虑。

这套系统的每一个设计，都在回答同一句话：
**"这条记录消除模糊了吗？"**

- 任务 → 什么时候做？做多久？优先级？
- 社交 → 和谁？上次联系是什么时候？亲密度如何？
- 财务 → 钱花在哪了？还剩多少？
- 知识 → 学了这个，跟我已知的什么有关？
- 创作 → 这件作品到什么阶段了？卡在哪里？

**模糊 → 记录 → 链接 → 清晰**，这就是系统运转的底层逻辑。

### 方法论植入

| 方法论 | 在系统中的体现 |
|--------|--------------|
| **CODE** | 灵感库(Capture) → 执行库/知识笔记(Organize) → 每周复盘(Distill) → Agent推送(Express) |
| **PARA** | 执行库=Projects · 社交/财务/科目基线=Areas · 灵感库=Resources · 已完成记录=Archives |
| **GTD** | #前缀统一收件箱 → 解析分流 → 状态逐级推进 → 每日回顾 → 执行 |
| **核心事件法** | 每天从"十年之河"借来的锚点任务，一件做完就值得 |
| **MOC导航笔记** | 用一条知识笔记串联多条知识点，构建知识地图 |

## 二、新增四张表详细设计

### 2.1 💰 财务流水表

**前缀指令**：`#账单` / `#财务`

**输入示例**：
```
#账单 午饭 28元 餐饮
#账单 买张宇数学书 65元 学习
#财务 兼职收入 500元 收入
#账单 滴滴打车 23.5元 交通
#账单 晚上聚餐 186元 社交
```

**字段设计**：

| 字段名 | 类型 | 说明 | 默认值 |
|--------|------|------|--------|
| 标题 | text | 消费/收入内容 | — |
| 金额 | number | 正数=支出，负数=收入 | — |
| 类型 | select | 支出 / 收入 | 支出 |
| 分类 | select | 餐饮/交通/学习/购物/娱乐/医疗/社交/其他 | 其他 |
| 支付方式 | select | 微信/支付宝/银行卡/现金 | 微信 |
| 日期 | datetime | 消费日期 | 今天 |
| 所属项目 | select | 关联项目（可选） | — |
| 备注 | text | 补充说明 | — |
| 创建时间 | auto | — | — |
| 最后修改时间 | auto | — | — |

**解析逻辑**：
- 无金额 → 警告提示
- `数字+元/块` → 金额
- `收入` → 类型=收入，金额取正
- 分类匹配：饭/餐→餐饮，车→交通，书/课→学习，衣服/淘宝→购物，电影/游戏→娱乐，药/医院→医疗，聚会/请客→社交

```
#知识 泰勒公式展开 数学 来源:张宇基础30讲 P120
```

| 字段名 | 类型 | 说明 | 默认值 |

| 知识点 | text | 核心内容（**用自己的话写**） | — |
| 类型 | select | 常青笔记/读书笔记/网络笔记/MOC/其他 | 常青笔记 |

| 标签 | text | 逗号分隔的自定义标签 | — |

| 关联灵感 | link:灵感库 | 关联到灵感（可选） | — |
| 创建时间 | auto | — | — |
| 最后修改时间 | auto | — | — |

**十年之河借鉴**：**四种笔记类型 + MOC导航笔记**

| 类型 | 用途 | 输入特征 |
|------|------|---------|
| 常青笔记 | 单个原子化知识点 | `#知识 泰勒公式展开 数学 ...` |
| 读书笔记 | 一整本书的笔记 | `#知识 《张宇18讲》要点 数学 来源:书籍 来源详情:张宇18讲` |
| 网络笔记 | 一篇文章/视频的笔记 | `#知识 B站高数视频 数学 来源:视频` |
| **MOC导航笔记** 🆕 | 串联多条知识点的导航 | `#知识 MOC-线性代数核心框架 数学 MOC 关联:矩阵运算,行列式` |

**MOC（Map of Content）操作指南**：
1. 学完一个专题（如线性代数）后，新建一条知识笔记
2. 类型选 MOC，标题以 `MOC-` 开头
3. 「关联记录」字段填写该专题下属所有笔记标题，逗号分隔
4. 在飞书Base里，通过「关联记录」的文本就能串起整个专题
5. 随着新笔记的加入，MOC可以持续更新，这就是"知识地图的生长"

**解析逻辑**：
- `来源:XXX` → 来源详情
- `数学/英语/政治/408/编程/管理/生活` → 分类
- `MOC` → 类型=MOC
- `关联:XXX,YYY` → 关联记录（多个用逗号分隔）
- `书籍/课程/视频/文章/经验` → 来源（自动匹配）

## 三、十年之河精华融入

### 3.1 核心事件法 🎯

**概念**：每天设定一件必须完成的事，其他都是加分项。这件做完了，今天就算值了。

**融入方式**：

每日推送头部新增一行：
```
🎯 【核心事件】今日必完成：做数学真题2010
  （今天其他事都可以放，这件事做完就值了）
```

**谁来设定**：
- 任务输入时标注 `【硬骨头】` → 自动成为当日核心事件
- 当日有多个硬骨头 → 权重最高的那个
- 无硬骨头 → Agent从P0任务中选截止日期最近的

**每周复盘中统计**：核心事件完成率 = 过去7天完成核心事件的天数 / 7

### 3.2 生日提醒 🎂

**概念**：在社交关系表中为联系人设置生日，Agent提前推送提醒。

**融入方式**：

社交关系表新增 `生日(datetime)` 字段（选填）。

输入方式：
```
#社交 张三 生日:1998/03/15 同学 ★★★
```

Agent每日推送新增：
```
🎂 生日提醒（未来7天）：
  - 张三 还有5天生日（3/15）→ 建议准备祝福
  - 李四 今天生日！→ 记得发消息
```

### 3.3 联系人时间线 🤝

**概念**：「十年之河」用 `[[张三]]` 在日记中链接，点击后展示所有互动记录。
你不需要双向链接，飞书Base的分组视图就能实现同等效果。

**操作方式**：
1. 在社交关系表创建一个「按联系人分组」的视图
2. 选择「联系人」作为分组字段，按「日期」降序排列
3. 效果：点开张三的分组，就能看到和他所有的互动时间线

**技术替代**：无需任何代码，纯飞书Base视图配置，30秒搞定。

### 3.4 习惯追踪（简化版） 💪

**概念**：「十年之河」每日记的习惯打卡 + 热力图。飞书Base不支持热力图，但可以用简化方案。

**融入方式**：

**方案**：不新增表，在**执行库**中给习惯性任务设置「重复周期」。
- 每日学习打卡 → 执行库存一条重复任务，每天标记完成
- 运动/阅读等 → 同一条任务，状态=进行中，每天在备注追加打卡

**或者用知识笔记做打卡记录**：
```
#知识 2026-06-29 运动打卡 生活 来源:经验
知识点：今天跑步3公里，俯卧撑50个
```
按日期搜索即可看到所有打卡记录。

> 注意：习惯追踪是需要投入维护成本的模块。**如果你觉得不值得投入精力，完全可以跳过**，先跑通其他四个模块。

### 3.5 人物关系显式化

**概念**：「十年之河」的人物笔记可以记录详细信息和关系。

**融入方式**：

在社交关系表中，同一「联系人」有多条记录时，可以**用飞书Base的记录详情页备注关系变化**：
- 第一记录：建立基础画像（关系标签、亲密度）
- 后续记录：每次互动追加，亲密度可以随互动自动调整
- 定期在Base中手动整理亲密度

## 五、模块联动与数据流

### 5.1 灵感 → 创作（转化链路）

```
灵感库: 一条好点子
  ↓ 判定可执行
#创作 标题 类型 灵感 关联灵感:原灵感ID
  ↓ 迭代更新
#创作 标题 类型 进行中/已完成
```

### 5.2 知识 ↔ 灵感（知识网络）

```
知识笔记「关联灵感」→ link到灵感库
知识笔记「关联记录」→ 文本串联其他笔记
  ↓ 按专题
MOC笔记 → 关联该专题下所有知识点
```

### 5.3 社交 → 项目（上下文串联）

```
社交活动「关联项目」→ link到执行库项目
  ↓
Agent检测到：张三在社交中提到了项目X → 推送提醒跟进
```

### 5.4 财务 ⇄ 项目（成本关联）

```
#账单 买数学书 65元 学习 关联项目:考研
  ↓
周报统计：各项目花费，考研学习支出XXX元
```

## 十、MOC导航笔记实践指南

### 什么时候创建MOC？

学完一个专题后（如线性代数全部学完、操作系统前三章看完）。

### 创建步骤

1. **输入**：`#知识 MOC-线性代数核心框架 数学 MOC 关联:矩阵运算,行列式,特征值,二次型,向量空间`
2. **等待心情好时**，打开这条记录
3. 在「知识点」字段中，按自己的理解写下这个专题的知识结构：

```
线性代数核心框架：
1. 矩阵运算（基础）→ 2. 行列式（计算工具）→ 3. 向量空间（几何解释）
   ↓                                                      ↓
4. 特征值与特征向量（核心定理）←———————— 5. 二次型（应用出口）
```

4. 每当你新学一个相关知识点，在「关联记录」中追加标题，更新MOC

### MOC的复利效应

- 第1条MOC：40%的知识是孤立的
- 第5条MOC：60%的知识点在MOC之间产生了交叉引用
- 第20条MOC：形成了一个真正的知识网络（这正是"十年之河"说的"第二大脑"）

## 十二、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储 | 飞书Base一体（非本地） | 已有基础设施，微信可触达，维护成本<5min |
| 社交表 | 单表（活动记录）非双表（联系人+活动） | 输入即完成，不需要先建联系人库再记录 |
| 记账 | 正数支出/负数收入 | 和支付宝微信流水概念一致，直觉操作 |
| 知识类型 | 含MOC类型 | 十年之河最有价值的设计，一键串联分散知识 |
| 习惯 | 不新建表 | 维护成本高，优先跑通核心链路 |
| 生日 | 放在社交表中 | 不单独建生日表，少一张表少一分维护 |
| 编辑器 | 飞书Base在线编辑 | ⭐心情好时在Base里批量整理、链接、建MOC |
