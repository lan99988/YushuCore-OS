# Example YushuOS plugin

Copy this directory, replace the example manifest, runner, and skill, then create `plugin.lock.json` with `yushuos lock-plugin --path <plugin-directory>`. Install a package with `yushuos install-plugin --path <plugin-directory>`. Installation verifies the lock and preserves the package as an immutable `plugins/<plugin-id>/<version>` directory. It does not select the version or enable the plugin. The lock detects package drift; it does not authenticate who created the package.

`plugin.yaml` is the Plugin Contract v1 surface (`contract_version: 2` for the V0.2 runtime): stable ID and version, domain/app/flow/storage type, supported runtime, dependencies, private plugin data path, configuration schema, fail-closed error policy, metadata-only audit policy, runner protocol, capability inputs/outputs/effects/intents/permissions, resource scopes, triggers and aliases, and independent implementation/verification/authorization/enabled states. Keep secrets and remote resource IDs in local bindings, not in this distributable package.

The runner uses the portable `yushuos_sdk` contract. It receives one JSON object on stdin and must return one JSON `Result` on stdout. Diagnostics belong on stderr. Core supplies the plugin's private `data_path` and (for authorized writes) shared `state_ledger_path` in the payload. Before a remote write, claim the original request ID with `StateStore.claim`; if it is already claimed, inspect the receipt instead of sending again. Record the final result with `StateStore.record`, and leave uncertain writes pending for readback. Core stores only resource identifiers in workflow checkpoints. The subprocess runs with a reduced environment, but local plugins are trusted code and are not OS-sandboxed.
