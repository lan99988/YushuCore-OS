# 系统健康检查规范

> 版本：v1.0 ｜ 生效：2026-07-24 ｜ 状态：设计冻结（仅观察，不修改）

---

## 1. 目的

为「个人混合管理系统」提供**可重复、可一键运行**的自我体检能力。

任何一次下述改动后，都应跑一遍健康检查，确认系统仍处于健康态：

- 移动 / 重命名目录
- 新增 / 删除 Skill
- 修改 / 新增 Schema
- 修改 Python 引擎
- 修改自动化（Automation）
- 飞书连接 / 凭证变更

健康检查的产出是一份**人类可读的健康报告**，明确指出每一项 PASS / FAIL，并在 FAIL 时给出原因与定位线索。

---

## 2. 设计原则（第一原则）

> **只观察，不修改。**

- ❌ 不自动修复
- ❌ 不自动修改文件
- ❌ 不自动迁移数据
- ❌ 不调用 AI 做诊断

健康检查脚本**只读**文件系统、只读飞书 `auth status`、只编译不执行业务逻辑。
任何修复动作由人决定，脚本只负责**暴露问题**。

---

## 3. 检查项目

共 **7 项检查**。脚本必须输出每一项的结果，最后汇总为 `System Status: READY` 或 `System Status: UNHEALTHY`。

> 路径约定：所有路径使用**真实中文目录名**（框架层面有 junction 桥接，但脚本应直接读真实路径，避免依赖 junction 解析）。
> 顶层 10 个目录：`00_系统核心（System）` `01_Skill能力库（Skills）` `02_执行引擎（Engine）` `03_领域模块（Modules）` `04_数据中心（Data）` `05_自动化工作流（Automation）` `06_外部连接（Integration）` `07_系统文档（Docs）` `08_工具脚本（Tools）` `09_临时文件（Temp）`

---

### 3.1 目录检查（Directory）

**检查内容**：核对 10 个顶层目录 + 关键子目录存在。

**必须存在的目录**：

| 目录 | 用途 |
|------|------|
| `00_系统核心（System）` | 注册表 / 长期记忆 / Agent 指南 |
| `01_Skill能力库（Skills）` | 所有 Skill（扁平一级，数字前缀） |
| `02_执行引擎（Engine）` | 输入解析 / 每日排程 / 数据分析 / 复盘分析 |
| `03_领域模块（Modules）` | 比赛管理等领域程序 |
| `04_数据中心（Data）` | 数据模型 / 数据版本 / 运行状态 |
| `05_自动化工作流（Automation）` | 自动化脚本 |
| `06_外部连接（Integration）` | 飞书 / 知识库等外部桥接 |
| `07_系统文档（Docs）` | 规范与蓝图 |
| `08_工具脚本（Tools）` | 工具脚本 |
| `09_临时文件（Temp）` | 缓存 / 导入暂存 |

**输出**：`目录: PASS` 或 `目录: FAIL（缺失：<目录名>）`

---

### 3.2 Skill 检查（Skill）

**检查内容**：扫描 `01_Skill能力库（Skills）/*/SKILL.md`，每个必须包含 **10 个标准信息段**（依据 `07_系统文档（Docs）/Skill规范.md`）。

**10 个必备段**：

```
基础信息  功能定位  触发方式  输入  输出
依赖      数据      权限      调用链  测试
```

**判定**：文件数 = N；含全部 10 段的文件数 = M。结果 `Skill: M/N`。
当且仅当 M == N 时该项 PASS。

**输出**：`Skill: 10/10` 或 `Skill: 8/10（缺失标准段：<Skill名> → <段名>）`

---

### 3.3 Schema 检查（Schema）

分两层校验：

**3.3.1 JSON 合法性**
遍历 `04_数据中心（Data）/数据模型（Schema）/**/*.json`，全部 `json.load` 成功。
**输出**：`Schema: K/K（JSON 合法）` 或 `Schema: FAIL（<文件> 解析错误：<原因>）`

**3.3.2 注册表一致性（Schema ⊆ Registry）**
- 读取系统注册表 `01_Skill能力库（Skills）/00_Skill注册中心（Registry）/SKILL.md` 中的「数据资产注册表」，提取全部模型名（当前 15 个）。
- 读取每个 Schema JSON 的 `model` 字段。
- 判定：每个 Schema 的 `model` 都必须出现在注册表模型集合中。
**输出**：`Schema 一致性: PASS` 或 `FAIL（<Schema模型> 不在注册表中）`

> 设计原则：Schema 是数据层真实世界的抽象，注册表是唯一资产清单。Schema 必须是注册表的子集。

---

### 3.4 Python 引擎检查（Engine / py_compile）

对 6 个核心引擎做 `py_compile` 语法校验：

| 引擎 | 路径 |
|------|------|
| input_parser | `02_执行引擎（Engine）/输入解析引擎/input_parser.py` |
| daily_scheduler | `02_执行引擎（Engine）/每日排程引擎/daily_scheduler.py` |
| calendar_sync | `02_执行引擎（Engine）/每日排程引擎/calendar_sync.py` |
| analytics_engine | `02_执行引擎（Engine）/数据分析引擎/analytics_engine.py` |
| weekly_deep_review | `02_执行引擎（Engine）/复盘分析引擎/weekly_deep_review.py` |
| competition_manager | `03_领域模块（Modules）/比赛管理（Competition）/程序/competition_manager.py` |

**判定**：编译通过数 / 总数。结果 `Engine: 6/6`。
当且仅当全部通过时该项 PASS。

**输出**：`Engine: 6/6` 或 `Engine: 5/6（失败：<文件> → <错误>）`

---

### 3.5 导入检查（Import）

在 `sys.path` 注入各引擎目录后，执行：

```python
import input_parser
import daily_scheduler
import calendar_sync
import analytics_engine
import weekly_deep_review
import competition_manager
```

确认跨目录引导块（`_ensure_engine_paths()`）生效、模块可加载。

**输出**：`Import: PASS` 或 `Import: FAIL（<模块> → <异常>）`

> 注：此项验证"运行期可加载"，与 3.4 的"语法编译"互补。

---

### 3.6 飞书连接检查（Feishu）

执行（只读，不触发写操作）：

```
lark-cli auth status
```

调用方式遵循既有约定（Node 直调 `run.js`，`--as user`）：
```
node <cli>/scripts/run.js auth status
```

**判定**：
- `bot` 状态为 `ready` → 必过
- `user` 状态为 `ready` 或 `needs_refresh`（下次调用自动续期）→ 视为可用

**输出**：`Feishu: PASS（bot:ready, user:<状态>）` 或 `Feishu: FAIL（<原因>）`

---

### 3.7 自动化检查（Automation）

**检查内容**：扫描 6 个自动化定义的 prompt，确认**无旧路径引用**（重构后已失效的相对路径）。

**已知需杜绝的旧引用模式**：
- `scripts/...`（脚本已迁至 `05_自动化工作流（Automation）/脚本/`）
- 根目录级 `input_parser.py` / `daily_scheduler.py`（已迁入 `02_执行引擎（Engine）`）
- 其他指向重构前路径的字符串

**读取位置**：`.workbuddy/automations/`（junction）→ 真实 `00_系统核心（System）/工作流定义/`。也可经 `automation_update` 工具读取。

**输出**：`Automation: PASS` 或 `Automation: FAIL（<自动化ID> 含旧路径：<片段>）`

## 5. 退出码与失败定位

- 全部 PASS → 进程退出码 `0`，`System Status: READY`
- 任一 FAIL → 进程退出码 `1`，`System Status: UNHEALTHY`，并在对应项输出**具体原因 + 定位线索**（文件名 / 行号 / 模型名 / 自动化 ID）

脚本**不得吞掉异常**：任何检查内部的报错都应转化为可读的 FAIL 原因，而非崩溃堆栈。

## 6. 实现约束（第一版）

- **第一版可单文件**：`08_工具脚本（Tools）/系统健康检查.py`
- **必须实现**：Skill 检查 / Schema 检查 / Python 引擎检查 / Feishu 检查（用户指定四必需项；Import 与 Automation 建议同版附带，成本低）
- **不实现**：自动修复、自动改文件、自动迁移、AI 诊断
- **未来扩展结构**（本版不强制，但命名需预留）：

```
08_工具脚本（Tools）/
└── 系统健康检查/
    ├── main.py
    ├── check_directory.py
    ├── check_skill.py
    ├── check_schema.py
    ├── check_engine.py
    ├── check_feishu.py
    ├── check_automation.py
    └── report.py
```
