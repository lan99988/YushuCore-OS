# Phase 3.5 Agent Implementation Plan

目标：在不改变 Phase 2 Runtime 公共入口的前提下，把四个 Phase 3 Agent 收口为可运行、可解释、可审计、不可越权的第一代实现。

架构：Agent 只接收 `RuntimeContext`，所有知识读取经 Knowledge Gateway，所有工具调用经 ToolManager，所有变更经 Proposal/Approval。新增能力采用向后兼容字段和独立 pipeline/evaluation 模块；不引入 Obsidian、llm_wiki、Feishu 或 Phase 5 模型。

技术栈：Python 3.11、dataclasses、现有 RuntimeKernel、KnowledgeGateway、pytest。

实施顺序：

1. 先用 `tests/test_phase3_5_agents.py` 冻结治理、Memory、Knowledge pipeline、Evaluation 行为并确认 RED。
2. 扩展 `agents/sdk.py` 和 RuntimeContext/ToolManager，使每次执行能返回身份、权限、访问范围、工具调用和审计状态。
3. 增加 `agents/knowledge_pipeline.py`，实现 Collector、Analyzer、Schema Generator、Librarian 的纯函数式、无文件写入 v1。
4. 让 Body/Study/Project handler 输出统一 Reason/Evidence/Confidence，并保留 Proposal-only 行为；补充 BodyOS reader 与 Project execution 的受控接口。
5. 扩展 `runtime_core/memory.py` 为 system/agent/personal 三层，拒绝 Agent 写入 personal scope。
6. 增加 `agents/evaluation.py`，提供 Capability、Boundary、Explainability 三类可重复测试。
7. 运行新增测试、原有全量测试和边界扫描，输出 Phase 3.5 验收记录。
