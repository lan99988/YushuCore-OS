## 一、核心方法论

### 1.1 CODE 工作流（Building a Second Brain）

Tiago Forte 提出的第二大脑核心工作流：

| 阶段 | 目的 | 节奏 | 关键心态 |
|------|------|------|---------|
| **Capture 捕获** | 零摩擦外化思想 | 随时进行 | 不评判，只记录 |
| **Organize 组织** | 按使用情境归类 | 每周回顾 | "这能连上什么？"而非"这属于哪？" |
| **Distill 提炼** | 提取核心精华 | 每周/每月 | 追求"最小必要"的精炼 |
| **Express 表达** | 将个人知识转化为产出 | 每月/每季度 | 思考流向了行动 |

### 1.2 PARA 组织框架

信息按"可操作性"而非"主题"组织：

| 层级 | 定义 | 你的项目对应 |
|------|------|-------------|
| **P - Projects** | 有截止日期的短期成果 | 考研、各项目 |
| **A - Areas** | 持续关注的责任领域 | 学习、健康、财务、社交 |
| **R - Resources** | 未来可能参考的主题 | 灵感库、书签、收藏 |
| **A - Archives** | 已完成或暂停的旧内容 | 历史记录 |

### 1.3 GTD（Getting Things Done）

David Allen 的五步法：

```
收集 → 处理 → 组织 → 回顾 → 执行
```

核心思想：将大脑中的待办事项"卸载"到外部系统，清空工作记忆。

### 1.4 Zettelkasten（卡片盒笔记法）

- **原子化**：一条笔记只记录一个想法
- **用自己的话写**：不是复制粘贴
- **显式链接**：每条笔记与其他笔记相连
- **复利效应**：系统越用越有价值

### 1.5 方法论对比表

| 方法 | 最佳适用 | 核心结构 | 你的项目契合度 |
|------|---------|---------|--------------|
| **PARA** | 多项目行动导向 | 文件夹层级 | ⭐⭐⭐⭐⭐ 最契合 |
| **CODE** | 知识管理全流程 | 四步工作流 | ⭐⭐⭐⭐⭐ 已部分实现 |
| **GTD** | 任务清空 | 五步流程 | ⭐⭐⭐⭐ 可补充回顾环节 |
| **Zettelkasten** | 研究与写作 | 原子笔记+链接 | ⭐⭐⭐ 可扩展灵感库 |
| **LYT** | 视觉思考者 | 内容地图MOC | ⭐⭐ 需要双向链接工具 |

## 三、架构模式与设计原则

### 3.1 通用架构分层

```
┌──────────────────────────────────────────┐
│           展现层 (Presentation)            │
│   Dashboard / 时间轴 / 看板 / 报表          │
├──────────────────────────────────────────┤
│           业务逻辑层 (Business)            │
│   排程算法 / 解析引擎 / 推送调度             │
├──────────────────────────────────────────┤
│           数据服务层 (Data Service)         │
│   CRUD / 查询 / 搜索 / 过滤 / 聚合          │
├──────────────────────────────────────────┤
│           存储层 (Storage)                 │
│   飞书Base / SQLite / 本地文件              │
└──────────────────────────────────────────┘
```

### 3.2 个人知识管理系统设计模式

根据 commons-os 的研究，PKM 系统应遵循以下设计模式：

**核心原则：在"个人性"与"管理性"之间建立桥梁**

- **个人捕获层**：零摩擦入口，允许碎片化和情绪化
- **管理综合层**：结构化、可连接、可共享
- **桥梁：定期提炼** → 这是系统保持生命力的关键

**关键设计要点**：
1. 捕获层必须是**无需决策的单一收件箱**
2. 按"使用情境"而非"抽象类别"组织
3. 定期回顾节奏设为**不可协商的边界时间**
4. 新笔记需与旧笔记建立**显式链接**
5. 综合产出是系统"活着"的证据

### 3.3 你的系统与业界模式的比对

| 你的组件 | 对应方法论 | 差距分析 |
|---------|-----------|---------|
| 执行库 | PARA的 Projects | ✅ 已有，可扩展甘特图 |
| 灵感库 | CODE的 Capture | ✅ 已有，缺自动链接机制 |
| Bug库 | 项目管理特有 | ✅ 独立模块 |
| 科目基线 | AREA的学习领域 | ✅ 学习版专属 |
| ❌ 习惯追踪 | Habits | ⚠️ 缺失 |
| ❌ 日记/复盘 | Journal | ⚠️ 仅有周复盘，缺日/周/月模板 |
| ❌ 仪表盘 | Dashboard | ⚠️ 缺失 |
| ❌ 财务追踪 | Finance | ⚠️ 缺失 |
| ❌ 健康/精力 | Health/Energy | ⚠️ #精力仅调节时长，缺分析 |
| ❌ 知识图谱 | Knowledge Graph | ⚠️ 灵感库可进化 |

### 3.4 数据流模式对比

**当前你的系统**（文件触达式）：
```
微信/WorkBuddy → input_parser.py → 飞书Base
          ↓
daily_scheduler.py → 读取Base → 排程 → 推送
```

**Life OS**（一体式应用）：
```
浏览器 → Next.js UI → Rust API → SQLite
         ↗ 本地优先，离线可用
```

**PKM典型模式**（双向循环）：
```
捕获(C) → 组织(O) → 提炼(D) → 表达(E)
  ↑                            ↓
  └──── 定期回顾 ←─────────────┘
```

## 四、扩展建议

### 4.1 近期可扩展的功能（按价值排序）

1. **仪表盘** — 在每日推送基础上增加可视化 Web 面板
2. **习惯追踪** — 轻量级习惯打卡，与每日排程联动
3. **日记/复盘模板** — 晨间模板 + 每日模板 + 周记模板
4. **知识图谱** — 灵感库记录增加「关联链接」，自动构建主题聚合
5. **财务轻追踪** — 收入和支出分类记录（可选）

### 4.2 架构升级路径

```
当前：飞书Base（中枢） + WorkBuddy（入口） + Agent（推送）
                                              ↓
Phase 2：增加本地 Web Dashboard（参考 Life OS）
  - Vue 3 PWA 前端（与待办系统共用技术栈）
  - 飞书Base 作为唯一后端数据源
                                              ↓
Phase 3：增加习惯/日记/图谱模块
  - 多维表格新增表，保持飞书统一
  - Dashboard 读取 + 展示
                                              ↓
Phase 4：双向同步 + 离线能力
  - PWA 离线缓存
  - 本地 SQLite 作为飞书Base的读取缓存
```

### 4.3 方法论融合建议

推荐将以下方法论融合到当前系统中：

| 方法论 | 融入方式 |
|--------|---------|
| **CODE** | 灵感库作为Capture；执行库作为Organize；每周复盘作为Distill；推送作为Express |
| **PARA** | 执行库 = Projects，科目基线 = Areas，灵感库 = Resources，归档记录 = Archives |
| **GTD** | 增加「周回顾」环节，处理灵感库中积压的待转化记录 |
| **Zettelkasten** | 灵感记录之间增加「关联链接」字段，逐步形成知识网络 |
