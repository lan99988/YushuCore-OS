# 任务分类机制：正式任务 vs 轻量任务

> 解决的问题：飞书任务框里的任务与执行库（Base）长期不一致——手动在任务框建的、或系统外的任务无法回流到执行库；同时并非所有任务都值得持久化进执行库。
>
> 本机制明确区分两类任务，并让系统自动按规则分流。

---

## 一、两类任务的定义

| 维度 | 正式任务（Formal） | 轻量任务（Lightweight） |
|------|-------------------|------------------------|
| **判定标记** | 无 `#临时` 标记（默认） | 带 `#临时` 标记 |
| **是否写入执行库** | ✅ 是（Base `执行库` 表） | ❌ 否（仅停留任务框） |
| **是否进入每日作战时间轴** | ✅ 是（排程器从 Base 读取并排程） | ❌ 否（排程器看不到） |
| **是否出现在飞书任务框** | ✅ 是（排程器自动创建） | ✅ 是（输入时直接创建） |
| **任务框标题特征** | 原样（如 `做数学真题`） | 带 `[临时]` 前缀（如 `[临时] 买牛奶`） |
| **典型用途** | 考试任务、项目里程碑、需长期追踪的事 | 顺手记的杂事、一次性提醒、手机端随手记 |

**核心原则：无标记 = 正式 = 入库；带 `#临时` = 轻量 = 仅任务框。**

---

## 二、输入侧：如何创建两类任务

所有入口统一在 `input_parser.py`：

### 轻量任务（仅任务框，不入库）
```bash
# 前缀形式
python input_parser.py "#临时 买牛奶"
python input_parser.py "#临时 交报告 【项目：项目A】【截止：2026/07/20】"

# 修饰符形式（效果完全相同）
python input_parser.py "#任务 买牛奶 #临时"
```
- 系统只在飞书任务框创建一条任务，标题自动加 `[临时]` 前缀；
- **不调用 Base 写入**，因此每日排程不会把它纳入时间轴；
- 支持可选 `【项目】` `【截止】` 等结构化变量，会写入任务描述便于回看。

### 正式任务（入库，走原有流程）
```bash
python input_parser.py "#任务 做数学真题 【项目：数学二】"
```
- 写入执行库 → 排程器读取 → 自动在任务框创建对应任务并排程。

## 三、反向同步：把任务框里的正式任务拉回执行库

飞书任务框里**手动创建、尚未入库的正式任务**，用以下命令一次性拉回执行库：

```bash
python input_parser.py "#同步任务框"          # 扫描并实际同步
python input_parser.py "#同步任务框 --dry-run" # 仅预览，不写执行库
```

### 分类规则（每条任务框任务依次判定）
1. 标题以 `[临时]` 开头 → **轻量任务，跳过**（本就不应入库）；
2. `status == done`（已完成）→ **跳过**（无需再入库）；
3. 标题已在执行库中存在 → **已同步，跳过**（去重）；
4. 其余（无 `[临时]` 前缀 / 未完成 / 执行库无同名）→ **正式任务，待入库**，写入执行库（默认 `P3 / 待收集 / 截止=任务框原截止日`）。

### 已知限制
- 飞书任务框列表接口对新创建任务有**短暂索引延迟**（约数分钟）。刚建的临时任务可能暂时不出现在 `#同步任务框` 列表里——不影响功能，因为临时任务本就被规则 1 跳过。
- 手动在任务框建的正式任务，若想立即入库，执行 `#同步任务框` 前可稍等片刻或重试一次。

## 四、判定流程图

```
用户输入
   │
   ├─ 含 "#临时" ─────────────► 轻量任务
   │                              └─► 仅飞书任务框（标题加 [临时]）· 不写执行库
   │
   └─ 不含 "#临时"（默认）────► 正式任务
                                      │
                    #同步任务框 扫描任务框时：
                       ├─ [临时] 前缀     → 跳过
                       ├─ 已完成(done)    → 跳过
                       ├─ 已在执行库      → 跳过（去重）
                       └─ 其余            → 写入执行库
```

---

## 五、运维要点
- 轻量任务真实创建路径已验证：`task tasks create --data @file --as user`，标题带 `[临时]`。
- `#同步任务框` 读取执行库使用 `--limit 200` + `--offset` 分页（Base API 上限 200），读取失败会**硬报错**而非静默当空集（避免误把已入库任务重复写入）。
- 任务框删除：`task tasks delete --task-guid <guid> --yes --as user`（高危操作，需显式 `--yes`）。
