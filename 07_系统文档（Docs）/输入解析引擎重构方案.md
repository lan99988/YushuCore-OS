## 2. 目标架构

### 2.1 目录结构（就地重构，路径不变）

`02_执行引擎（Engine）/输入解析引擎/` 由单文件升级为 **Python 包**，目录名不变（保证 `sys.path` 引导块与自动化调用路径零改动）。

## 4. 兼容原则（硬性）

1. **外部调用接口零改动**：`python input_parser.py "#任务 写文章 [--dry-run]"` 行为完全不变。
   - 实现方式：保留 `input_parser.py` 为 5 行 shim，转发到 `输入解析引擎.main`。
   - 因此 6 个自动化（`每日作战时间轴推送` 等）、健康检查 `check_import` 均无需改动。
2. **指令集不变**：`#任务 #灵感 #Bug #精力 #配置 #账单 #社交 #创作 #知识 #孵化 #复盘 #排程到日历 #深度* #注意力审计 #习惯* #比赛 #临时 #同步任务框` 全部保留，行为一致。
3. **字段 / 飞书表 / Skill 一律不改**（本阶段只做职责拆分）。
4. **输出一致**：相同输入 → 相同 `format_output` 文本（见验证方法）。
5. **跨引擎延迟导入保持**：`daily_scheduler/calendar_sync/competition_manager` 仍为 handler 内 lazy import，不提升为模块级，避免加载顺序耦合。

## 6. 验证方法（保证"输出完全一致"）

### 6.1 Golden Output 测试（核心，确定性）
- **dry-run 模式天然确定性**：`--dry-run` 不写飞书、不触发网络，输出仅依赖输入文本与少量字段。
- 步骤：
  1. 重构前：对固定命令集（`#任务 写文章`、`#灵感 想到方法 【项目：408】`、`#Bug 崩溃 【严重程度：崩溃】`、`#复盘 7 --dry-run`、`#习惯 喝水 每天3次`、`#比赛 列表 --dry-run`、`#临时 买牛奶`）跑旧 `input_parser_old.py --dry-run`，保存 stdout 为 `golden_old.txt`。
  2. 重构后：同命令跑新引擎 `--dry-run`，保存 `golden_new.txt`。
  3. 比对：`diff` 应**逐字节一致**。
- **日期字段归一化**：`build_record` 对财务/社交/知识用 `datetime.now().strftime("%Y/%m/%d")` 注入当天日期。比对时需：
  - 两次运行在**同日同分钟**内完成，或
  - 在 comparator 中把 `日期`/`YYYY/MM/DD` 字段正则替换为占位符后再 diff。
- 测试脚本落点：`09_临时文件（Temp）/golden_test/`（验证用，不进版本库）。

### 6.2 健康检查门禁
- 每次迁移后跑 `python "08_工具脚本（Tools）/系统健康检查.py"`。
- 关注：`Python检查`(py_compile 6/6)、`Import检查`(input_parser 可加载——shim 保证)、`Schema检查`(不受影响)。
- 必须 `System Status: READY` 才进下一步。

### 6.3 跨引擎冒烟
- `#排程到日历 --dry-run`：验证 `daily_scheduler`+`calendar_sync` 延迟导入仍通。
- `#比赛 列表 --dry-run`：验证 `competition_manager` + `set_config` 注入仍通。

## 7. 回滚方案

| 触发条件 | 动作 |
|----------|------|
| 任一步 golden diff 不一致 | 停手，定位该步 handler，回退该文件到 `input_parser_old.py` 对应段 |
| 健康检查 FAIL | 不改 health check，先修引擎；若 10 分钟内无法修复 → 整体回滚 |
| 整体回滚 | 删除 `输入解析引擎/` 新模块，`input_parser.py` 恢复为 `input_parser_old.py` 全量内容，`git checkout v1.2-pre-refactor` 亦可 |
| 长期锚点 | `input_parser_old.py` 保留至阶段 5（Repository）完成、新架构稳定后删除 |

> **回滚零影响保证**：因 `input_parser.py` 始终保留为对外入口（先 shim 后整体替换），自动化与健康检查的调用路径在重构全程不变。
