## 2. 激活与边界

### 激活条件

以下任一匹配，立即加载本 skill：
- 用户提到「比赛」「参赛」「报名」「初赛」「决赛」「奖状」「奖金」「报销」
- 用户提到「competition」「注册」「入围」「晋级」
- 用户发来大段文字（>50字）且内容包含赛事名称、日期、成绩等结构化信息
- 用户以 `#比赛` 开头输入

### 绝不激活

- 用户只提到「游戏」「电竞」「对战」但没有具体比赛名称 → 不触发
- 用户只是闲聊「昨天那场比赛真好看」→ 不触发
- 用户明确在讨论考试、学习、工作安排 → 不触发

## 3. 核心工作流（必须遵守）

无论用户输入什么内容，按此流程执行：

```
Step 1 - 解析
    ↓    从用户文字中提取：比赛名称、阶段、日期、结果、金额、人员、地点、备注
Step 2 - 诊断
    ↓    判断操作类型：创建 / 更新阶段 / 上传图片 / 查看列表 / 查看详情 / 帮助
Step 3 - 构造命令
    ↓    按本文件的「构造规则」将提取结果拼为一条或多条 `#比赛` 命令
Step 4 - 展示确认
    ↓    输出结构化命令序列给用户，等用户说"确认"或"执行"
Step 5 - 执行
    ↓    用户确认后，逐条执行命令
Step 6 - 报告
    ↓    告知用户执行结果，输出当前比赛总览
```

**关键规则：Step 4 不可跳过。没有用户确认，绝不执行写操作。**

## 4. 输入解析规则

### 4.1 比赛名称提取

- 优先取：书名号《》中的内容 | 引号「」中的内容 | 斜杠 / 之间的内容
- 其次取：紧跟在「比赛」「赛事」「参赛」「参加」后的连续文本
- 再次取：第一段中出现的明显赛事名称（如含「第X届」「大赛」「杯」「赛」字样的短语）
- 如果无法确定 → 输出"请确认比赛名称"并列出候选

### 4.2 关键字段提取

| 字段 | 解析规则 | 示例 |
|------|----------|------|
| 日期 | `YYYY年M月D日` / `YYYY-MM-DD` / `YYYY/MM/DD` / `M月D日`（自动补年） | 2026年6月27日 → `2026/06/27` |
| 结果 | 晋级/未晋级、获奖/未获奖、入围/未入围 | 入围决赛 → 晋级 |
| 成绩 | 数字+分、奖项名称（一等奖/二等奖/金奖） | 94.00 → 94.00分 |
| 费用 | `(\d+)元` / `费用[：:]\s*\d+` | 59元 |
| 姓名 | 出现在「姓名」「选手」「人员」后的中文名 | 苏雨菱 |
| 组别 | 本研组/高职组/专业组等 | 本研组 |
| 地点 | 出现在「地点」「地址」「城市」后的文本 | 深圳市 / 线上 |
| 链接 | 以 `http://` 或 `https://` 开头的 URL | https://www.cnccac.com/ |

### 4.3 阶段映射

| 用户原文关键词 | 对应阶段 |
|----------------|----------|
| 报名、注册、提交 | `报名` |
| 初赛、笔试、选拔赛 | `初赛` |
| 决赛、总决赛 | `决赛` |
| 成绩、分数、奖项、排名 | `成绩` |
| 奖金、奖励金 | `奖金` |
| 报销、费用报销 | `报销` |

特殊判定：
- 如果用户提供了初赛**和**决赛信息 → 分别构造两条命令
- 如果用户提到「仅一轮」「直通」且没有初赛信息 → 初赛`跳过`，决赛正常
- 如果用户提到初赛但决赛「未入围」「未晋级」→ 决赛状态设为`不适用`

## 5. 命令构造规则（精确模板）

### 5.1 创建比赛

```
输入示例: 2026年第九届计算机技能应用赛，线上比赛，苏雨菱，广州科技职业技术大学
命令模板: #比赛 创建 <比赛名称> 【日期：<日期>】【地点：<地点>】【人员：<人员>】【链接：<URL>】
实际命令: #比赛 创建 2026年第九届计算机技能应用赛-Word 【日期：2026/06/27】【地点：线上】【人员：苏雨菱】
```

规则：
- 比赛名称后加 `-Word` `-Python` 等科目后缀（如果用户提供了科目）
- 日期从文字中提取，找不到则用用户提供的报名/考试日期
- 无地点则写"线上"或留空
- 无人员则写"苏雨菱"（如果用户提到女朋友/伴侣名字）或"待定"
- 有比赛链接（如官网URL）则用【链接：<URL>】填入，无则省略

### 5.2 更新报名阶段

```
模板: #比赛 <名称> 报名 【截止：<日期>】【费用：<金额>】【备注：<文本>】
```

规则：
- 截止日期 = 报名截止日（如无则用比赛日期前推）
- 费用 = 报名费（从「报名费」「费用」「支付金额」提取）
- 备注 = 主办方信息、支付方式、备注说明

### 5.3 更新初赛阶段

```
模板: #比赛 <名称> 初赛 【日期：<日期>】【结果：晋级/未晋级】【备注：<文本>】
跳过:  #比赛 <名称> 初赛 跳过
```

规则：
- 结果只允许 `晋级` / `未晋级`
- 如果用户说「入围决赛」「进入下一轮」→ 结果 = 晋级
- 如果用户说「未通过」「淘汰」「未入围」→ 结果 = 未晋级
- 备注 = 成绩、组别、是否入围等信息

### 5.4 更新决赛阶段

```
模板: #比赛 <名称> 决赛 【日期：<日期>】【结果：获奖/未获奖】【备注：<文本>】
不适用: #比赛 <名称> 决赛 不适用
```

规则：
- 结果只允许 `获奖` / `未获奖`
- 如果用户给出奖项名称（一等奖/亚军等）→ 结果 = 获奖
- 如果用户说「未获奖」「无奖项」→ 结果 = 未获奖
- 如果初赛未晋级 → 决赛 = 不适用
- 备注 = 奖项详情、名次

### 5.5 更新成绩阶段

```
模板: #比赛 <名称> 成绩 【成绩：<文本>】【奖状：<文本>】
```

规则：
- 成绩 = 最终获得的奖项/分数
- 奖状 = 证书名称或"待下载"
- **不自动设置「奖状已上传」**（此字段已删除）

### 5.6 更新奖金阶段

```
模板: #比赛 <名称> 奖金 【金额：<数字>】【状态：未开始/进行中/已完成】
状态: 未开始 / 进行中 / 已完成
```

### 5.7 更新报销阶段

```
模板: #比赛 <名称> 报销 【金额：<数字>】【状态：未开始/进行中/已完成】【备注：<文本>】
```

### 5.8 上传图片附件

```
#比赛 <名称> 上传凭证 <路径>   → 报名费凭证（报名费截图、报销凭证）
#比赛 <名称> 上传报销 <路径>   → 同上，都存入「报名费凭证」
#比赛 <名称> 上传奖状 <路径>   → 奖状图片（证书/奖状截图）
```

注意事项：
- 路径支持 Windows 格式：`D:\xxx\xxx.jpg` 或 `C:\Users\xxx\Desktop\cert.jpg`
- 路径有空格时用引号包裹
- 只支持常见图片格式：JPG、PNG
- 上传前自动复制到当前目录（lark-cli 安全要求），上传后自动清理

### 5.9 查看

```
#比赛 列表        → 全部比赛总览（进度条+完成率）
#比赛 <名称>      → 单场比赛详情
#比赛 帮助        → 帮助信息
```

## 7. 错误处理

### 7.1 命令执行失败

| 错误信息 | 含义 | 处理 |
|----------|------|------|
| `比赛管理表未注册` | TABLES 字典缺少配置 | 检查输入引擎集成 |
| `未找到比赛「xxx」` | 名称写错或不存在 | 用 `#比赛 列表` 查看已有比赛找正确名称 |
| `文件不存在` | 上传路径不对 | 要求用户提供正确路径，或检查路径格式 |
| `更新失败` | Base 写入问题 | 先用 `--dry-run` 测试，确认命令格式 |
| `初赛结果只能为：晋级/未晋级` | 参数值不合法 | 检查输入值，修正为合法值 |
| `没有要更新的字段` | 无 `【key:value】` 参数 | 添加参数，或确认是否只是查看详情 |

### 7.2 重试策略

- 同一错误连续出现 2 次 → 停止重试，向用户报告当前状态、已尝试方法、剩余假设
- dry-run 成功但实际执行失败 → 检查 Base 网络连通性（lark-cli TLS 握手可能超时）
- 超时错误 → 稍后重试（网络波动）

## 8. 考试自动解析指南（常见场景）

这是用户最频繁的场景——女朋友参加比赛，提供页面截图文字。按以下步骤：

```
Step 1: 检查是否包含「学校」「组别」「成绩」等字段
        → 说明这是一场比赛结果，需要记录

Step 2: 提取考试/比赛基本信息
        - 比赛名称：页面顶部的活动/赛事标题
        - 参赛者：姓名
        - 组别：本研组 / 高职组
        - 科目/方向：如 Word、Python、C语言

Step 3: 提取初赛信息
        - 初赛日期：考试时间
        - 初赛成绩
        - 初赛奖项
        - 是否入围决赛

Step 4: 提取决赛信息
        - 决赛日期
        - 决赛奖项（如有）

Step 5: 提取支付信息
        - 如有支付截图，识别金额 → 报名费
        - 如有支付时间 → 用于备注

Step 6: 构造命令序列并展示确认

Step 7: 如果用户提到「证书XX月可下载」→ 设置自动化提醒
        - 用 automation_update 创建一次性提醒
```
