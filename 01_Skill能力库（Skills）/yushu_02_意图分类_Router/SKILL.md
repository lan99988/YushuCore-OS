## 功能定位

处理无前缀的自然语言输入，判断意图（task/idea/bug/energy/chat）、关联项目、提取字段。**只判断不写入**。

## 触发方式

用户输入不以 `#` 开头且与个人管理相关（任务、学习、灵感、Bug、精力等）。

## 输入

自然语言（无前缀）。

## 输出

`{type, fields...}`（type = task / idea / bug / energy / chat）。

## 依赖

- 系统注册表（Token / 表 ID）
- 下游：yushu_04_飞书操作_Processor / yushu_05_问答校准_Processor / yushu_06_每日排程_Processor

## 权限

- write：runtime/_energy_status.json（当 type=energy）
- admin：无

## 一、意图分类规则

### 1.1 任务（→ type: "task"）

**判断依据**：表达中有明确的**动作意图**或**待办指向**。

| 关键词示例 | 说明 |
|-----------|------|
| 做、完成、需要、必须、要、搞定 | 直接动作 |
| 处理、安排、准备、记得、别忘了 | 提醒类 |
| 今天/明天/这周 + 要做的事 | 时间约束 |
| 学会、看完、做完、刷完 | 进度目标 |
| 买、取、交、发、联系 | 具体待办 |
| 还没、忘了、差点 | 遗漏提醒 |

**典型例句**：
- "今天把数学真题2010做了" → task
- "需要买一盒笔" → task
- "英语单词还没背完" → task

**产出格式**：
```
标题: 做数学真题2010
所属项目: 考研（自动推断）
轻重缓急: P2-紧急不重要（默认）
状态: 待收集
截止日期: （如有时间约束则提取）
精力消耗等级: 中（默认）
预估耗时: （如无则留空）
是否为今日硬骨头: false
```

### 1.2 灵感/观点/知识（→ type: "idea"）

**判断依据**：表达的是**想法、观点、知识点、建议、感悟**，没有明确的待办动作。

| 关键词示例 |
|-----------|
| 想到、觉得、发现、突然想到 |
| 应该、也许、可以试试、建议 |
| 原来、其实、本质上、是因为 |
| 有个想法、有个点子、有个思路 |
| 分享一个方法、记住、这个有用 |
| 对于XX，我认为 |
| 纯描述信息、知识点、事实 |

**典型例句**：
- "想到可以用Anki卡片背408概念" → idea
- "我觉得番茄钟不适合数学，容易打断思路" → idea
- "今天学到一个记忆方法：间隔重复" → idea

**产出格式**：
```
标题: 用Anki卡片背408概念
所属项目: 考研
灵感原文: <原始输入全文>
转化状态: 待孵化
优先级预判: P2-紧急不重要（默认）
触发场景: （如有上下文则记录）
```

### 1.3 Bug/问题（→ type: "bug"）

**判断依据**：涉及**故障、异常、报错、不正常行为**。

| 关键词示例 |
|-----------|
| 报错、crash、崩溃、闪退 |
| 有问题、坏了、不行、卡住 |
| 出bug、出错了、异常 |
| XX功能用不了、XX不正常 |

**典型例句**：
- "项目A的登录页面一直转圈" → bug
- "考研英语App闪退了" → bug

**产出格式**：
```
标题: 考研英语App闪退
所属项目: 考研
Bug简述: <原始输入全文>
严重程度: 功能缺陷（默认）
修复状态: 待修复
```

### 1.4 精力状态（→ type: "energy"）

**判断依据**：描述今天的**身体状态、精神精力、睡眠**。

| 关键词示例 |
|-----------|
| 状态、精力、精神、累、困、疲惫 |
| 没睡好、失眠、头疼 |
| 今天没状态、状态差、状态好 |

**产出格式**：
```
type: energy
status: 差/一般/好
raw: <原始反馈>
```

### 1.5 闲聊（→ type: "chat"）

**判断依据**：明显与个人管理无关的日常对话、问候。
**处理**：直接回复，不写库，不进后续流程。

## 二、项目关联检测

### 2.1 显式提及

| 关键词 | 所属项目 |
|--------|---------|
| 考研 / 数学二 / 英语二 / 政治 / 408 | 考研 |
| 项目A~D | 对应项目 |
| 生活 / 日常 / 家里 | 生活区 |

### 2.2 上下文推断

- 学习、刷题、考试相关 → 考研
- 工作、代码、开发相关 → 对应项目
- 纯个人生活 → 生活区

### 2.3 未匹配处理

- 任务未匹配 → 默认为"全局"
- 灵感未匹配 → 放入全局灵感库
- 多项目可选 → 标记让问答 skill 处理

## 三、字段提取规则

### 3.1 轻重缓急推断

| 信号 | 映射 |
|------|------|
| 紧急、马上、立刻、今天必须 | P0-重要紧急 |
| 重要、关键、核心、必须完成 | P1-重要不紧急 |
| 有空、顺便、可以的话、常规 | P2-紧急不重要（默认） |
| 不着急、以后、有空再说、随便 | P3-不重要不紧急 |

### 3.2 截止日期提取

"今天" → 当天 | "明天" → 次日 | "这周五" → 解析为具体日期
"7月5号/日" → 解析为 yyyy/MM/dd | "截止到XX" / "之前完成" → 提取截止日

### 3.3 精力消耗等级推断

| 行为 | 精力等级 |
|------|---------|
| 做题、刷题、复习、攻克、深入 | 高 |
| 整理、看视频、听课、阅读、背诵 | 中（默认） |
| 背单词、看笔记、简单的、回顾 | 低 |

### 3.4 预估耗时

- 显式："花2小时""大概要90分钟""半小时" → 转换为分钟
- 隐式：合理推断（不确定时留空）

### 3.5 硬骨头检测

关键词："硬骨头""难啃""今天必须搞定这个""再难也要"
约束：每天最多1-2个，连续标记时提醒

### 3.6 多轮次任务检测

**判断**：包含"分N次""分N批""N轮""N遍"等关键词

```
"分9次学习完" → N=9, 各轮次截止日均匀分布
"刷3次真题" → N=3
```

**处理原则**：执行库只写一条总记录，第1次飞书任务由「yushu_04_飞书操作_Processor」创建，后续轮次由自动化迭代。

1. 回顾最近使用中发现的问题
2. 修复后版本号+1
3. 通知用户修正内容
